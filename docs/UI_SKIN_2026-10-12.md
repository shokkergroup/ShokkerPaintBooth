# SPB Pro Skin (2026-10-12) - one calm, upscale layer over the whole UI

Owner brief: "polish the UI/UX ... more upscale, more of a real app feeling. MUST lose the vibecoded look,
keep the same good functionality." Target feel: Adobe Substance / Photoshop 2025 dark, Figma, Linear, Resolve.

File: `css/spb-skin-pro-20261012.css` (linked LAST in `paint-booth-v2.html`, `?v=spb-skin-pro-20261012x`).
Nothing else is edited: no HTML structure, ids, classes, JS behaviour or hidden controls change.

## Why `@layer spb-skin` (read before touching it)
The old CSS is a specificity war (`body:not(#spb-pl):not(#spb-plc1)...x10 .x {...!important}`, 40+ polish files,
an inline `<style>` in the page). Adding more selectors makes it worse. Cascade layers fix it structurally:
**an `!important` declaration inside a layer beats EVERY unlayered `!important` declaration, whatever its
specificity or source order.** So every skin rule is `@layer spb-skin { html:not(.spb-skin-off) .x { prop: v !important } }`
with a simple selector. Rules:
1. Every declaration that must win carries `!important` (a layered NORMAL declaration loses to unlayered ones).
2. Never `!important` a property that JS sets inline for behaviour (display, width/height of canvases, zone
   swatch colours, positions). Inline `style="...!important"` still beats the skin; those elements are noted in
   `S2_PROGRESS.md`. Use `:not([style*="background"])` to spare inline-coloured buttons/swatches.
3. Keep selectors flat (class or id + one qualifier). Specificity only matters between two skin rules.
4. Never add `:not()` stacks, never edit the old files. Re-skinning = edit this one file.

## Kill switch
`localStorage.SPB_SKIN_OFF='1'` (set in DevTools or `window.localStorage`), reload: a tiny inline script before the
`<link>` adds `class="spb-skin-off"` to `<html>` and every rule (all wrapped in `html:not(.spb-skin-off)`) stops
matching, so the pre-skin UI returns untouched. Remove the key to turn the skin back on.

## Two layers: `spb-skin` (hand-written) over `spb-parity` (generated)
`@layer spb-skin, spb-parity;` - skin beats parity, parity beats everything unlayered.
Why parity exists: every earlier polish wave (spb-polish-c/d/e/f/g/h in `css/spb-clean-default-20260829.css` + the
`js/ui/spb-polish-*.js` data-pl / data-pld icon taggers) is gated to `body:is([data-look="classic"],[data-look="compact"])`.
The 14 gallery looks (carbon = the owner's, nord, ...) never got Title Case labels, line icons, the tidy header, the
"Menus" overflow at 1100, so they looked vibecoded while classic looked clean. `_ui_polish_2026-10-12/tools/gen_parity.py`
re-emits those rules re-gated to `:not([data-look="classic"]):not([data-look="compact"])` (plus the `:not(.spb-gallery-look)`
rules and the important declarations of the ungated rules) between `/* ==PARITY-BEGIN== */` and `/* ==PARITY-END== */`:
`python _ui_polish_2026-10-12/tools/gen_parity.py out.css --inject css/spb-skin-pro-20261012.css` (run from project root;
re-run after the clean-default CSS changes). Classic/compact are untouched by parity. Excluded on purpose: the 2026-10-12
iRacing ID box layout (`.field-id`, `.pe-*`, `.header-number-mode`), kept as in carbon (label over number, checks stacked).
Guards (top of the skin layer) re-hide hidden-on-purpose elements the parity layer would unhide: Easy button,
`#zoneQuickViewBar`, `#drawZoneHint`.
Hand-written waves live in `/* ==W2-BEGIN== */ ... /* ==W7-END== */` blocks (sources in `_ui_polish_2026-10-12/parts/`,
`tools/inject.py W3 parts/W3.css` replaces a block).
**Typography trap:** the polish layer hides raw label text with `font-size:0` and paints `::after{content:attr(data-pl)}`.
Never set `font-size` on such elements (`.header-command-btn .gear-btn .spb-tb-summary .spb-mode-opt .zoom-btn
.section-header-label .studio-label`), size their `::after`; otherwise the raw text shows twice.

## Tokens (custom properties, top of the file; per-look overrides below them)
- Surfaces, 3 steps + sunken: `--sk-bg #121417` app, `--sk-panel #181b20`, `--sk-raised #1f232a`, `--sk-hover #262b33`,
  `--sk-field #14171b` (inputs, slightly sunken).
- Lines: `--sk-line rgba(255,255,255,.07)`, `--sk-line-2 .12` (controls), `--sk-line-3 .2` (hover).
- Text: `--sk-text #e7e9ed`, `--sk-text-2 #a3aab5` (secondary), `--sk-text-3 #727985` (disabled/hint only).
- ONE accent for selection / focus / active: `--sk-accent #4fbcd2` (+ `--sk-accent-hi`, `--sk-accent-soft` 14% fill,
  `--sk-accent-line` 45% line). Shokker orange `--sk-cta` is ONLY the RENDER button (the one gradient allowed).
- Status (rare, text/icon only): `--sk-danger #e5675f`, `--sk-ok #55c08a`, `--sk-warn #d9ad4f`.
- Shape: `--sk-h 28px` standard, `--sk-h-sm 24px` compact, `--sk-r 6px`, `--sk-r-sm 4px`; spacing 4/8/12/16.
- Type: `--sk-font "Segoe UI Variable","Segoe UI",Inter,system-ui`; body 12-13px, secondary 11px, section headers
  11px / 600 / .04em tracking (uppercase only on these small headers), weights 400/500/600, `tabular-nums` on numbers.
- Legacy variables (`--bg-dark --bg-card --text --border --accent --pro-* --pl-*`) are re-pointed to these on `body`
  (important, in-layer) so older rules that read them inherit the new palette for free.
- Looks: the 16 `body[data-look=...]` values only swap tokens (surface tint + accent): oled = true black, hi-contrast =
  stronger lines + white text, studio-warm / copper = warm graphite + amber accent, nord / dracula / monokai /
  solarized / midnight / emerald / linear-dark carry their own accent hue, the rest are the graphite default.

## Component rules (summary)
- Buttons: 28px, radius 6, transparent ghost on `--sk-raised`, 1px `--sk-line-2` border, hover `--sk-hover`, no
  glow/gradient/shadow, 12px/500 sentence-case labels (all-caps bold shouting is removed except small section headers).
  Primary = RENDER only (orange). Active/selected = accent text + `--sk-accent-soft` fill + 1px accent line.
- Header nav buttons are quiet ghosts; PRO / CHAT is a segmented control; active mode = accent.
- Inputs/selects: `--sk-field`, 1px line, radius 6, 28px (24px compact), focus = 2px accent ring offset 1px.
- Sliders: 3px neutral track, neutral fill (`--sk-text-3`), accent only on the 12px thumb and on focus.
- Checkboxes / toggles: native-feeling 14px, `accent-color: var(--sk-accent)`.
- Scrollbars: 10px, transparent track, `rgba(255,255,255,.14)` thumb, hover .24.
- Panels: flat `--sk-panel`, one hairline divider, no boxes inside boxes (inner cards lose border+shadow, keep spacing).
- Min readable text 10px (7-9px micro text is lifted to 10px; where layout needs it, labels shorten via CSS only).
- Motion: 120ms colour/background/border only; honour `prefers-reduced-motion`.
