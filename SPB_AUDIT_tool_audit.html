Shokker Paint Booth — Toolbar Tool Audit

Deep functional audit of every Zone & Layer tool: do they work exactly as intended? Plus a roadmap to use the toolbar to its full potential. Generated 2026-06-20 00:15 via a 46-agent workflow.

Bottom line. The toolbar is fundamentally healthy: every selection and paint tool produces correct output for normal drag-based use (rect, lasso, wand, select-all, ellipse, gradient fill, fill bucket, smudge, pencil, dodge, recolor all do the right thing on the pixels). The problems are not "tool is broken," they're broken PROMISES — keybindings that conflict (M, I), tooltips that advertise behavior the code doesn't deliver (Edge Detect "finds boundaries" but fills interiors; rect "click again to commit" is unreachable; Pick Item "(I)" never fires), a feather slider shown for 6 tools that nothing reads, and zone-vs-layer parity gaps where the same tool behaves differently or worse on a layer. Two genuine data-loss/visual bugs need attention: a tiny Replace-mode ellipse wipes the whole selection before its size guard, and colorbrush on a layer uses a richer engine on the first dab than on the drag (plus a transparent-pixel alpha miss on that first dab). The biggest opportunity is a "make tooltips true" pass plus a keybinding cleanup, then closing the zone/layer parity gaps so the painter gets identical behavior in both modes. None of these crash; all are fixable with localized edits.

🔝 Top recommendations (in order)

  1. Fix the two data-loss/visual bugs first: guard the tiny-Replace ellipse before it wipes the selection (move the size check above the mask-clear/undo), and unify the colorbrush layer engine + set alpha on the first dab so layer strokes are consistent and visible.
  2. Run a 'make every tooltip true' pass — reconcile Edge Detect's name/intent, the rect two-click claim, Pick Item (I), Surprise-me (R), and layer gradient types — so the UI stops advertising behavior the code doesn't deliver.
  3. Build a single keybinding registry that owns all shortcuts and detects collisions at load, fixing the M (mute vs marquee) and I (pencil vs pick-item) conflicts at the root.
  4. Wire the auto-feather slider (shared post-commit step for all six selection tools) so the control that's already shown everywhere actually works.
  5. Close zone/layer parity gaps: match the fill tolerance metric, and either implement or hide the non-linear gradient types on layers.
  6. Fix the gradient preview line zoom math (drop the double `* zoom`) so painters can aim gradients at any zoom level.
  7. Add an on-canvas mode HUD plus toasts for silent no-ops/locked-layer/too-small cases to surface hidden capability and stop 'is it broken?' confusion.
  8. Make destructive tools (dodge/recolor/smudge) clip to the active selection and honor stylus pressure family-wide.

Move the degenerate-size guard `if (rx < 1 || ry < 1) return;` ABOVE the mask-clear/pushUndo lines so a too-small ellipse never pushes undo or wipes the mask. medium colorbrush
layer		 A colorbrush stroke on a PSD layer looks different at its start than along the drag. The first (mousedown) dab runs paintColorBrush with full dynamics — brush shape, pattern brush, symmetry, Gaussian falloff — but the drag dabs detect the active layer canvas and switch to _paintOnLayerAt, a plain radial arc with no shape/pattern/symmetry. So non-round shapes, pattern brushes, and mirror modes appear on the single click dab and silently vanish as soon as you drag. In the colorbrush drag branch, when _activeLayerCanvas is set keep calling paintColorBrush() (it writes paintImageData and _flushPaintImageDataToCurrentSurface mirrors it into _activeLayerCtx at line 19760) instead of _paintOnLayerAt, so layer strokes use the same engine as zone strokes start-to-finish. paint-booth-3-canvas.js:2671-2675 `_paintOnLayerAt(...)` on drag vs mousedown 3435 `paintColorBrush(pos.x, pos.y)`. ✓ FIXED
medium colorbrush
layer		 The first colorbrush dab is invisible when painting onto a transparent area of a layer. _paintColorBrushAt writes only RGB and never sets the alpha byte, so on an alpha-0 pixel the color goes in but the pixel stays transparent. The drag dabs (via _paintOnLayerAt, a canvas fill) do set alpha, producing a confusing 'click does nothing, drag works' result on empty layer regions. (No issue on the opaque composite where alpha is already 255.) In _paintColorBrushAt set alpha toward opaque like pencil does: `data[idx+3] = Math.max(data[idx+3], Math.round(255*alpha));` so color brushed onto transparent layer pixels becomes visible on every path. (Pairs naturally with the colorbrush drag-engine fix above.) paint-booth-3-canvas.js:15256-15258 sets only RGB, no `data[idx+3]` assignment; contrast paintPencil 15546 `d[idx+3] = Math.max(d[idx+3], alphaByte);`. ✓ FIXED
medium recolor
both		 Recolor replaces the BACKGROUND color with the FOREGROUND color, which matches its tooltip literally but is a usability trap: it never samples the pixel under the cursor. The user must manually set BG to the exact color they want gone, unlike every standard color-replacement brush. Because BG defaults to #000000 and most pixels under the brush aren't black, painters get 'nothing happens'. Also inconsistent: the mousedown dab calls paintRecolor directly with no symmetry while the drag wraps it in _applyWithSymmetry, so the first dab ignores mirror modes. On recolor mousedown, auto-sample the pixel under the cursor as the target color (e.g. set _backgroundColor = getColorAt(x,y) or use a stroke-local target) so it behaves like a real Color Replacement brush; keep manual BG override as an option. Route the mousedown dab through _applyWithSymmetry for parity with the drag path. paint-booth-3-canvas.js:15383-15386 target taken from `_backgroundColor`, never sampled from canvas; mousedown 3458 (no symmetry) vs drag 2712 (`_applyWithSymmetry`). ✓ FIXED
medium gradient
zone		 The live gradient preview line and end-dots are drawn in the wrong place at any zoom other than 100%. The preview multiplies coordinates by zoom, but the region overlay buffer is full canvas resolution and zoom is applied only via CSS scaling — so the guide is effectively scaled by zoom twice and lands far from the cursor. 🚀 Improvement roadmap — use the toolbar to its full potential

Run a 'make every tooltip true' pass: audit all toolbar/help-card tooltips against the actual keydown handler and commit code, and fix whichever side is wrong (Edge Detect intent, rect two-click, Pick Item (I), Surprise-me (R), layer gradient types, the dead feather slider). high impact · M
The single biggest source of confirmed defects is broken promises, not broken code. Every tool basically works; users lose trust and time chasing behavior the UI advertised but doesn't deliver. Truthful tooltips are the cheapest credibility win.
Build one central keybinding registry/table that owns every canvas+zone shortcut, detects collisions at load, and is the single source of truth (replacing the two competing document keydown listeners). high impact · M
M and I collisions are symptoms of two files each grabbing keys independently with no arbitration. A single registry kills the whole class of 'shortcut silently shadowed' bug and makes future tools safe to add.
Close zone/layer parity gaps so a tool behaves identically in both contexts: unify the colorbrush layer engine with the zone engine, match the fill tolerance metric, and implement (or hide) the non-linear gradient types on layers. high impact · M
Painters switch between zone and layer constantly; tools that look or select differently depending on context feel arbitrary and erode the 'it just works' feel. Parity makes the toolbar predictable.
Make destructive selection tools respect an existing selection family-wide: dodge/recolor/smudge should clip to the active regionMask, with a clear 'painting outside selection' affordance when none exists. medium impact · M
This is standard Photoshop behavior every painter expects; right now these tools spill outside the selection. One shared selection-clip helper fixes all three and prevents accidental edits.
Add a stroke-start auto-sample to Recolor (sample the pixel under the cursor as the target) so it works like a real Color Replacement brush, keeping manual BG as an override. medium impact · S
As shipped, most users get 'nothing happens' because BG defaults to black. Auto-sampling turns a confusing trap into the obvious, expected behavior with a tiny code change.
Wire the stylus pressure pipeline through to every brush-family tool (dodge already computes pressure-modulated radius/opacity but discards them; verify recolor/smudge/colorbrush too), and surface a pressure-dynamics toggle. medium impact · M
Pressure is computed and thrown away for dodge — a wasted feature. Honoring it across the brush family unlocks the tablet workflow that serious painters expect, for little extra code.
Add a lightweight on-canvas mode HUD / status chip showing the active tool, its modifier hints (Shift/Alt), and live tolerance/feather values, plus a one-key cheat-sheet overlay. high impact · M
Discoverability is the second-biggest theme: feather, selection modifiers, edge-bounded fill, and gradient types are all powerful but hidden. A persistent HUD turns hidden capability into used capability and reduces 'is it broken?' confusion.
Wire and standardize the auto-feather slider as a shared post-commit step for all six selection tools, with a live preview of the feathered edge. medium impact · S
The control already exists and is shown everywhere — it just isn't read. Connecting it (one shared helper) instantly upgrades every selection tool with soft edges, a feature painters use constantly for blending finishes.
Add safety rails to commit paths: guard degenerate-size selections before any mask-clear/undo push, and show a non-blocking toast ('Selection too small', 'Painting on locked layer', 'Nothing under brush matched') instead of silent no-ops. medium impact · S
Silent destructive failures (tiny Replace ellipse wiping the selection) and silent no-ops are the worst UX — the user can't tell whether the tool is broken or they did something wrong. Cheap toasts make the toolbar feel responsive and trustworthy.
Add the missing-but-expected selection accelerators: Invert Selection, Grow/Shrink by N px, Select Similar across the whole canvas, and a 'commit selection as new layer' shortcut. medium impact · L
These are table-stakes selection operations any painter coming from Photoshop reaches for; their absence forces tedious manual re-selection. They build directly on the existing regionMask plumbing.

✅ Verified working as intended

  • Rectangle Select (zone) — drag/release commits correctly: caches overlay, honors selection mode + Shift-square + Alt, fires overlay/preview, undoable.
  • Lasso (zone) — closeLasso commits a freehand selection into the region mask as intended.
  • Magic Wand (zone) — color-tolerance flood fill writes the region mask correctly (Euclidean² metric).
  • Select All by Color (zone) — selects all matching pixels into the mask as advertised.
  • Elliptical Marquee (zone) — drag commit works: rasterizes the ellipse with optional Shift-circle, honors selection mode, undoable (only the M shortcut and the tiny-Replace edge case are buggy).
  • Gradient fill (zone) — fillGradientMask applies all gradient types correctly at raw coords, undoable, refreshes overlay/preview (only the on-screen preview line is mis-positioned at non-100% zoom).
  • Gradient (layer) — paints FG->BG / FG->transparent honoring opacity/reverse, refuses on locked layer, undoable (limited to linear/radial types).
  • Fill Bucket (layer) — refuses locked layers, floods in layer-local coords, opacity-blends toward FG, commits with layer undo (only the tolerance metric differs from zone).
  • Smudge (both) — consistent engine on mousedown and drag, color travels via the smudge buffer, hardness falloff, undoable (only mid-stroke size changes misbehave); Q keybind is conflict-free.
  • Pencil (both) — hard-edged FG footprint, forces opaque alpha, correct pencil semantics, honors brushSize/opacity (right-click-BG and fast-stroke interpolation are the gaps).
  • Dodge (zone) — correct screen-toward-white lighten math, bounds- and alpha-safe, brush spacing/stabilizer/symmetry on drag (selection-clip and stylus pressure are the gaps).
  • Recolor (both) — replaces target with FG color blended by opacity/flow/falloff/match-closeness exactly per its literal tooltip (the UX trap is no auto-sampling, not incorrect math).

Fixes are being applied surgically and synced to both trees; the Status column updates as each lands. None of these are crashes — every tool produces correct output for normal use; the work is making the promises true and closing zone/layer parity gaps.
