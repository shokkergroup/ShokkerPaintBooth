## Repo facts
- mcp/server/index.js line ~117 builds `{type:'image', data, mimeType}` blocks (preceded by a text block "image: <name>"); no `structuredContent` anywhere. Server hand-rolls JSON-RPC; `initialize` (line 140) currently ignores `params.clientInfo`.
- Codex lane already proved Codex only (CLI 0.124.0). Nothing in repo tests ChatGPT, Responses API, or Agents SDK.

## Would the owner's Claude Desktop MCP run prove anything for OpenAI clients?
No. It proves only Claude Desktop's own rendering. Each client has its own tool-result-to-model adapter (Codex PR 5600 exists precisely because that adapter was missing; ChatGPT staff say images are not guaranteed). Codex needs its own run (already done once, 2026-10-01); ChatGPT would need a Developer Mode connector test.

## Recommendation
1. Assume vision only for Claude Code, Claude Desktop (verify once) and Codex with an image-capable model. Assume NO vision for ChatGPT connectors, hosted Responses MCP, Agents SDK, and unknown clients.
2. Fallback for blind clients (specified, not built): every image-returning tool (`spb_look_at_paint`, `spb_mark_elements`, `spb_preview`) additionally returns, as TEXT, (a) the `spb_describe_paint` text description, (b) the app's finder guess as numbers (boxes/parts), and (c) the literal label: "UNVERIFIED: this client cannot see the paint; confirm in the app." Never claim "I looked and see ..." from such a client. Keep the image block too (harmless where dropped), but for known-blind clients omit it so Agents-SDK-style clients do not ingest a ~100k-token base64 string as text.
3. Detection: server reads `params.clientInfo.name` in `initialize` (also `capabilities`) and stores it per session. I could NOT find documented clientInfo.name values for Claude Desktop, Claude Code, ChatGPT or Codex (searches returned nothing). Do not hard-code guessed strings: add a one-line debug log of clientInfo on each initialize, collect real values from the owner's actual runs, then build an allow-list (vision-known) and treat everything else as blind. A user override env/setting ("this client sees images: yes/no") is the safe backstop.
4. Cheap extra test for ChatGPT: it would need a public HTTPS endpoint (connectors cannot reach localhost), so a ChatGPT test is nontrivial; flag as owner decision.
