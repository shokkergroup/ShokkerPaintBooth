## WP12 - online / MCP refinish on a FLAT paint asks first (DONE)

**Defect (WP9):** on a flat paint the online model called `describe_paint` -> `refinish{target:numbers|sponsors|stripes | exclude}` with no boxes and the handler applied the finder's UNCONFIRMED guess (5/6 prompts), and the reply invented certainty ("found the numbers by eye", "all 19 of them").

**Fix (`js/spb-pro-ai.js`):**
- `refinish` handler: when the paint has no layer for a named element (target OR exclude), no `boxes` were given and that element is not confirmed on THIS paint (taught by the buyer's box / an AI `mark_elements`, the buyer pressed Yes, or `_taughtNow == sig`), it calls the new `refinishAskFirst()`: pushes the SAME card the typed sentence gets (`elemCardHtml`: tinted picture + Yes / No, I will show you / There are none; or the draw-a-box card when the finder found nothing), opens the panel, queues nothing, and returns to the model `{ok:true, status:"needs_confirmation"|"needs_the_buyer_to_show", element, nothing_changed:true, shown_to_buyer, note:"Do not claim ... changed, found or counted ... An MCP client that can see the paint should call look_at_paint + mark_elements with boxes ..."}`. The card's Yes re-runs the buyer's own sentence (`_reqText`; for MCP a sentence built from the args) through the normal flow, which now passes the confirmed check.
- "There are none on this paint" (pressed on a card made for this paint) is remembered from the log: a later refinish TARGETING that element returns `status:"none_on_this_paint"` (honest, nothing changed); as an EXCLUDE it is dropped (no junk exclusion). Excluding an element the finder did not find at all proceeds with the existing honest note ("I could not find the numbers ..., so I could not leave them out").
- Unknown exclude words are ignored (they used to become "sponsors").
- Tool result honesty: `by eye` wording rewritten; new `kept_out` (what the zones really exclude) and `honesty` ("This change covers that colour EVERYWHERE it is (no exclude was given): <measured overlap note> Never tell the buyer the numbers / sponsors / stripes were left alone ... unless they are listed in kept_out") - fixes WP9-B's false "left alone" claims on the PSD car.
- `describe_paint`: each element now carries `app_guess_found`, `confirmed_on_this_paint`, and `places` ONLY when confirmed; the note says it is an unconfirmed guess, never to state counts / "found", and that refinish will ask first.
- `refinish` description: states the flat-paint ask-first behaviour + new `mark_mode` / `mark_colour` / `spread` params (WP5 pass-through).
- PSD path unchanged (no flat element -> no gate).

## WP5 - mark_elements modes

**`js/spb-pro-elements.js`** (VERSION `wp5-2026-10-03a`):
- `ringBg` (outer band 12-40 px, clusters >= 25 % = background, busy -> box-edge colours), `aaRim` (blend rim, alpha 0.15-0.92: a solid pruned panel pixel is never re-added), `dtRect` / `thickOf` (chamfer DT, 2 x p95).
- `colourRegion` (colour_in_region): colour auto (largest non-background cluster + close shades chained within 70 and >= 30 %) or hex list / names (names resolved to the paint's own colour in markElements); refuses a colour equal to the ring paint or absent from the box; adaptive tolerance 20-56 (or `tolerance` 8-80) and "closer to the target than to the background"; breadth-first flood with budget = min(12 % of the sheet, the call's 25 % left); `spread` box / connected (default) / sheet; thickness guard per outside piece (> 1.6 x the in-box thickness -> its thick part (an opening by a disk of radius 0.8 x 1.6 x t) is cut out, only what stays connected to the box is kept, `capped:true` + body-paint reason); growth cap 4 x; budget cut without a panel -> box only + "over 12 %" reason.
- `logoRegion` (logo): every in-box pixel farther than 30 from the ring colours, 2 px closing, specks < 24 px out, enclosed holes of ring colour stay out (other-colour holes = plate), rim, clipped to the box, `touched_edge`.
- glyph = WP2 code untouched (hash-identical, S7); per-box `hint` when glyph px < 35 % of the box's non-background px (suggests mode logo; no auto-switch).
- `teach()` dispatches on `opts.mode`. `teachBoxes()`: mode by kind (`modeFor`), per-mode box gates (glyph as before; logo area <= 0.12; colour_in_region short side >= 0.003), call-level 25 % cap, per-box fields (`pixels_selected, share_of_box_pct, share_of_sheet_pct, outside_box_px, touched_edge, capped, cap_reason, colour_used, colour_source, other_colours_in_box, background`), `candidates` <= 4 (numbers glyph = WP2 maybe_more; others `candidatesFor` on a 512 downsample: net dead space skipped, stripes same thickness 0.6-1.6x + length >= 0.04 + area <= 1.6 x length x thickness so letters of the same stroke are not stripes; logos 0.4-2.5 x size, not inside a same-colour panel), `spread:"sheet"` auto-adds look-alikes with score >= 0.7 (max 6, `via:"sheet"`), `timing_ms`. `_cache` keeps the net `P` / `R`. `sheet(size, {kind, candidates})` tints only that kind in a colour that CONTRASTS with it and draws candidates dashed green.

## WP3 defects fixed inside WP5 (after the coordinator's WP3-done message; VERSION `wp5-2026-10-03b`, tokens `spb-pro-elements.js?v=20261003wp5c`, `spb-pro-ai.js?v=20261003wp5c`)
Note: WP3 paints 1-10 ran on the pre-WP5 build, 11-15 on `wp5-2026-10-03a` (the test server serves root files live).
1. **"There are none"**: `mark_elements {kind, none:true}` (boxes not needed) records it for this paint (`_elemNone[kind] = sig`), closes pending cards of that kind with the same note the card's None gives, reply `{ok, none:true, nothing_changed:true}`. `refinish` with that element as TARGET -> `status:"none_on_this_paint"`; as EXCLUDE -> dropped. **An EXCLUDE never asks first any more** (coordinator: a safety, not a target): declared none -> ignored, not found -> honest note, found-but-unconfirmed -> the zone excludes the app's guess and the note says it is a guess. Only a TARGET of numbers / sponsors / stripes needs the confirmation. Gate `pw/wp12_askfirst.py`: flat 11/11 (new 1b exclude proceeds, 1d none:true x3), psd 2/2.
2. **Low-contrast digits / plates**: `maskFor('numbers:fill' | ':outline')` now decides per MARKED place (`subPerBox`): fill = the solid colour (lowest edge ratio) among the big colours of that place, outline = the thinnest, and a plate (biggest, solid, spanning the place, digits inside) is neither. Fixes streetstock (ring bigger than the fill), legends (each number its own fill colour) and bmw (digits on a white plate) on synthetic S13. NOT fixable by colour: dirtsprint black-fill digits on a black body (the fill IS the body colour; only the outline differs) - documented, the reply cannot select it.
3. **Logo tiles**: decision = a tile / plate IS part of the decal by default (the truth layers include it), and the per-box `note` says "the whole decal was taken, its plate / tile (#hex, N %) included: to change only the lettering call again with lettering:true". New `lettering:true` (mark_elements; logo mode) = the plate colour counts as background too (S14). rt2000's band behind white words is the same case (lettering:true).
4. **Stripes**: (a) silvercrown: a ring colour that is >= 1.5x denser inside the box (and >= 15 % of it) is the stripe, not background (S12); growth cap 4x -> 25x (a box over a short piece of a long swoosh is normal; the thickness guard + 12 % share cap stay). (b) formulavee: auto skips anti-alias FRINGE clusters (a blend of another cluster and the body lying on the edge), takes the core, rim 3 px (S11; the metallic S4 still takes all three shades). (c) bmw textured body: ring background = clusters >= 25 % plus clusters >= 8 % until 85 % of the ring (max 5). (d) skmodified: a stripes / sponsors element zone added while a numbers element zone of ours exists is placed just BELOW it (`priority = numbers index + 1` in queueEditZones).
Synthetic `elements_modes_test.js`: **14/14** (10 design sheets + S11-S14 from WP3). Real-TGA re-check of these four on the WP3 folders: see the bridge section.
