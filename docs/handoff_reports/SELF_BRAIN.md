## 1. Design  [DONE]

1. **State reader `SpbSelfHelp.state()`** - pure snapshot, every read wrapped: `paint` = none | flat | psd (from `_psdLayers` with an `img`; layer names + roles via `SpbProCar.roles()`, hidden flags); `zones` = count, selected index (`selectedZoneIndex`), per zone {name, muted, base/finish, colourMode, pattern, spec count, catch-all} (raw `zones` array, no heavy describeAll); `carMap` = parts known? (`SpbProCar.map()` / `missing(['hood','left side'])`); `mode` = pro | easy (`shokker_ui_mode` / body class); `last` = the last helper action + `_spbLayerRev` / preview-image signature before and after (ai.js passes `{lastAction, changed}`). Node tests inject a fake state object instead.
2. **Question understanding `classify(text)`** -> one of how_do_i(goal) / what_is(word) / where_is(control) / why_not(expected effect) / stuck (what now / confused / lost) / can_i(capability) / explain_state ("what do I have loaded", "what is on my car"). Rule regexes first (cheap, deterministic), then the goal is matched against a TOPICS table (built from `how_do_i.md` entries + `ui_map.json` ids when SELF-MAP lands, seeded today from `app_controls.json`'s 35 controls + my hand list of ~40 goals) by stemmed word overlap + synonyms ("shiny slider" -> spec strength, "the colour thing" -> base colour mode); the knowledge library (`SpbAIKnowledge.searchScored`) is the fallback text source. It NEVER claims an order: imperative design / edit sentences (make / paint / add / put / turn ... without a question word) return null.
3. **Answer builder `answer(text, state)`** -> `{intent, text, steps[], cites[], chips[], doIt?}`: numbered steps naming the exact control label + where it is; steps already satisfied by state are skipped ("Zone 2 is already selected"); missing preconditions come first ("you have a flat paint, so there are no layers to sort - here is how to find the numbers instead"); a "Do it" chip when the helper can do step 1 itself (safe + reversible: select a zone, open the Layers panel / zone detail, run the numbers finder, refresh the preview, unmute a zone, switch colour mode to solid via the zone kit through the normal chat order so Undo covers it); an "I'm still stuck" chip -> the next-simplest path or the support checklist. Every answer ends with ONE forward question.
4. **Why-not diagnostics `diagnose(state, expected)`** - 12 checks, each `{id, test(state), say, fix, doIt}`: no paint loaded; no zone; no zone selected; zone muted; colour mode source / finish while a colour was wanted; solid colour on a brings-its-own-colours finish (flattens it - use Hue); pattern opacity 0 / pattern hides base; spec-only change invisible in the flat preview (switch to the spec view); wrong layer hidden / restrict-to-layer on a hidden layer; a lower-index zone covers this one (lower index wins); preview not re-rendered (layer rev unchanged); Easy mode (the Pro controls are in Pro). Ordered by how often they bite; the first 1-3 that fire are reported.
Routing (ai.js): `send()` -> edit brain / designer / advisor keep their claims; then `SpbSelfHelp.answer` for help intents BEFORE `supportSend` unless the support classifier says ingame / render / error (those keep the support checklist); `offlineAskCore` calls it just before `offlineHowto`; `offlineCanHandle` returns true for it so a key never sends a "how do I" to the paid model. Chips: `chips()` prepends `SpbSelfHelp.chips(state)` (state-aware, max 4) ahead of the generic list.
