## 1. Design (grounded in the code)

**Where it lives:** a section INSIDE `js/spb-pro-advisor.js` (`stackSlots / stackPlan / stackAnswer`), not a new module: every existing harness (B1 `intricate_run.js`, convo / tool / fuzz / adv_fp / corpus / gold / scenario runners) loads the advisor already, so no runner hooks are needed and the gate measures what ships. Exported as `SpbProAdvisor.stackPlan(text, env)` for tests and other tiers.

**1 Parse (layer slots, reusing the advisor's parsers):** the ask is split into clauses at layer connectors (with / over / under(neath) / on top / topped with / plus / and a / layered / finished in / commas). Each clause is typed by small word tables:
- `pattern` = paint-art words (carbon fibre, weave, kevlar, camo, hex, honeycomb, mesh, diamond plate, checker, plaid, houndstooth, chevron, stripes-as-pattern, scales, snake / dragon / tiger / leopard, marble, wood grain, tessellation, geometric, triangles, circuit, splatter, tribal, aztec, celtic, deco, paisley, floral, swirl, waves, topographic, pixel / digital, glitch, graffiti, damascus, feathers, chainmail, grid, crosshatch, stars, dots ...);
- `spec` = shine-texture words (flake, metal flake, glitter, sparkle, shimmer, pearl flake, brushed / grain, hammered, frosted, sandblasted, orange peel, holographic / iridescent / prism, ripple, guilloche / engine turned ...) and paint-art words used with a spec cue (texture / spec / ghost / only in the light / in the sun / under it);
- `base` = everything else that names a colour (`colourOf`) or a look (candy, pearl, metallic, chrome, satin, matte, gloss, gunmetal ...); a `like X` / named finish (`findFinishesIn`) becomes the base.
- `top` = clear-coat words (satin top / matte clear / gloss clear / wet top) = a SHINE CONSTRAINT on the base, not a separate layer.
- `scale` per textured layer: fine / tight / small / micro / crushed / "crushed to 20%" / "N% scale" / big / bold / huge / oversized -> 0.05-5 (crushed to N% = N/100, fine 0.5, micro 0.35, big 1.6, huge 2.2); `intensity` (opacity): subtle / faint / ghost / hint -> 35, soft / light 50, default 70, bold / strong / loud 90, explicit "N% opacity / strength".
- `parts` = the existing `targetOf` (hood / roof / stripes / sides / numbers ...); `constraints` = the existing negation spans (`negPhrases` -> `dislikes` -> `SpbProRank.avoidSet`, hard exclusion), `KEEP_RE` (keep my colour -> base stays a shine-only finish on colour "source"), loudness words (subtle / classy / tasteful / not too loud / understated -> budget).
A STACK = at least two different layer slots AND a layering cue (>= 2 clauses, or with / over / under / on top / pattern / texture / layered). Anything else returns `null` and the advisor runs exactly as today.

**2 Plan (lanes that already exist):** base = `SpbProRank.search(base words, types base+monolithic, own:'takes' when a colour is named)` re-scored by the card (colour hue match, shine constraint, loud); pattern = `search(pattern words, types pattern)` with a NAME boost (the head noun in the item name: "carbon fibre" -> Carbon Fiber); spec = `search(spec words, types spec)` fused with a concept canon read from the catalogue names (flake / stardust / starlet for sparkle; brushed; hammer / peen / dimple; frost; pearl / nacre / mica; carbon / kevlar / twill; holo / iridescent / prism / diffraction).
**Pairing rules from the measured atlas + cards** (each rejected pair moves to the next candidate and the reply says why):
- P1 sparkle / flake / holographic spec needs a clearcoat that is not dead matte: base `shine` matte/semi-matte -> swap to the next satin/gloss base UNLESS the buyer named matte (then keep it and say the flake will only read at an angle);
- P2 the spec card's own `avoid` ("matte base colours", "gloss") vs the base's shine class -> next spec;
- P3 pattern contrast vs the base lightness `L`: dark base (L < 28) + a pattern whose card says it vanishes on dark bases (or `con` < 20) -> next pattern; light base (L > 72) + "lost on light bases" -> next;
- P4 busy budget: base `busy` + pattern `busy` <= 7 (two busy layers fight);
- P5 loudness budget when the ask is subtle / classy / not too loud: base loud <= 3, every texture layer loud <= 2;
- P6 no double metal art: a full-metal mirror base (chrome) + a metal-texture spec keeps only spec items whose card pairs with chrome/metal.

**3 Answer:** `kind:'stack'` reply = text with layer rows (Base: X - why / Pattern: Y at scale S, intensity I - why / Shine: Z - why) + 2 alternative stacks, delivered as `kits` (the EXISTING kit card UI + `useKit` = one queue, one Undo). The Base item's card carries `stackWith {pattern, spec_patterns}`; `applyPlan` merges them into the base step (ONE zone: `finish` + `pattern {id, opacity, scale}` + `spec_patterns [...existing, {id, opacity, scale}]`, `region.part` for a part, lower index wins); the Pattern / Shine items carry `stackPart:true` and plan zero steps (their rows are shown, the base step applies them). `cards` = the main stack's three cards (noUse) so every consumer sees the layer kinds. "show me more" after a stack re-plans with the shown keys excluded.
`suggest_finishes`: when the ask is a stack (or `stack:true`), returns `stack:[{layer, key, name, why, scale, intensity}]`, `alternatives`, `apply` (the one zone call) and rows led by the stack layers.

**4 Explain:** every `why` is one line from the card (`look`, `pair`) or the measured shine (`shineWord`), plus the pairing rule that fired, never marketing.
